# Retune Core Platform — Milestone Roadmap

**Spec:** `docs/superpowers/specs/2026-09-12-core-platform-design.md`

The spec is implemented in eight milestones, plus a ninth that extends it to cover application deployment, listed as out of scope in the original spec. Each milestone gets its own detailed plan in this folder, written after the previous milestone is merged so it can build on the real code. Each milestone ends in software that runs and is covered by tests.

| # | Milestone | Spec sections | Deliverable |
|---|---|---|---|
| M1 | **Enroll & check-in** | 2, 3 (tokens, enrollment, server trust, revocation), 4 (check-in only), 11 (tenants, tokens, devices, audit) | Server with internal CA + agent API; token CLI; agent CLI enrolls with pinned server cert and checks in over mTLS; E2E test |
| M2 | Inventory, commands, agent state | 4 (full), 5, 6, 3 (cert renewal, unenroll) | bbolt local state + offline queue; Windows inventory collector; ad-hoc commands with results; cert renewal; `410` unenroll |
| M3 | Admin API, auth, console shell | 3 (admin auth, audit), 12 (devices, tokens, audit, admins) | Local accounts, sessions, CSRF, TOTP, roles, `bootstrap-admin`; React console embedded in server; YAML config file |
| M4 | Packaging & deployment | 2 (on-prem vs cloud, `behind-proxy`), 14, 16 | Agent as Windows service + WiX MSI; Docker image + compose; `behind-proxy` TLS mode; sweepers with advisory locks |
| M5 | Groups & assignments | 7, 8 | Static/dynamic groups with rule language → SQL; include/exclude assignments; effective-set in check-in; status rollups |
| M6 | Script deployments | 9 | Script library + versions; scheduler on agent (once/recurring, run-as user); detection/remediation; console pages |
| M7 | Configuration profiles I | 10 (engine, registry, service, local_group_members, file) | Profile model + versions; agent reconcile loop; conflict detection; revert on removal; profile editor |
| M8 | Configuration profiles II | 10 (firewall, windows_update, bitlocker + key escrow) | Remaining handlers; BitLocker key escrow with audited viewing; full-system E2E |
| M9 | Application deployment | extends the core-platform spec (out of scope there); see `docs/superpowers/specs/2026-09-13-m9-app-deployment-design.md` | winget packages as a new `app` item kind, reusing the M5 assignment engine and M6 agent scheduler; install/uninstall intent on the assignment; per-device history; console pages; full-system E2E |
| M10 | Agent self-update | extends the core-platform spec (out of scope there); see `docs/superpowers/specs/2026-09-14-m10-agent-self-update-design.md` | agent builds as a new `agent` item kind, assigned to groups; version-stamped builds, hash-verified download, supervised swap and automatic rollback on a failed check-in; console pages; full-system E2E |
| M11 | Hardening | extends the core-platform spec; see `docs/superpowers/specs/2026-09-14-m11-hardening-design.md` | Ed25519-signed agent builds with an offline release key and an embedded trust list; `retune-sign`; success inferred at check-in; `-race` in CI; tenant-scoped single-row queries |
| M12 | Compliance | extends the core-platform spec; see `docs/superpowers/specs/2026-09-15-m12-compliance-design.md` | server-evaluated compliance policies (twelve rule types) as a new `compliance` item kind, assigned to groups and mirrored into item status; evaluation on inventory ingest, a 15-minute sweeper and on demand; admin API for policy CRUD, per-device and per-policy results, a fleet dashboard, and CSV export; console overview and compliance pages; full-system E2E |

**Status:** M1 through M12 are implemented and merged.
